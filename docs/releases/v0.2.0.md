## Highlights

- The plugin now has a configuration page: sidebar **Plugins** → the **Local Search** card in the **Official plugins** group.
- Machine paths, the Anytxt endpoint, and both result caps are editable there, and a save applies to the next search instead of the next restart.
- **Test connection**, directly under the Anytxt endpoint, probes the address in the field without saving it first and answers in one line, so a wrong endpoint or a closed Anytxt GUI surfaces before a search fails.

## Changes

- `search`: unchanged tool surface; `local_search_files`, `local_search_content`, `local_search_fragments`, `local_search_read`, `local_search_status`.
- `scopes`: `workspaceRoot`, `workRoot`, `personalRoot`, and `allRoots` are editable on the page and read per call.
- `engines`: `esPath` and the Anytxt endpoint are editable on the page; `esEncoding` is a `gbk` / `utf-8` choice on the page, while the schema still accepts any `TextDecoder` label so a 0.1 profile keeps activating.
- `security`: the page writes only the plugin's own configuration; the tools stay read-only. The Anytxt endpoint must be local and the content engine reports `ANYTXT_ENDPOINT_REMOTE` instead of failing activation; the Test control's route `GET /dsh-local-search/api/status` refuses cross-site requests and applies the same local rule to an unsaved draft; AnyTXT redirects are refused rather than re-POSTed elsewhere. The profile patch remains the authority for `timeoutMs`.
- `install`: a failing probe links to the engine's official download page. `es.exe` and Anytxt are separate products whose licences allow use but not redistribution, so the package never bundles, downloads, or installs them.
- `docs`: the README covers the card and the Test control; `docs/architecture.md` records why fields are volatile, why `timeoutMs` is excluded, where the Test seam sits, and why the card's artwork is the page's; `docs/extending-engines.md` records the per-engine config debt.
- `ui`: the page is built only from the shipped UI primitives and theme tokens, and lays fields out as sections over a grid that seats two columns from 460px up, so installed UI skins restyle it without changes.
- `artwork`: a new multi-colour `icon.svg` (gradients, no `currentColor`) rides the manifest `icon`, so it shows on the bundle card, npm, and the README. The Official plugins card keeps the page's default artwork: that slot resolves icons from a hard-coded map of the four built-in pages, so a third-party card cannot supply its own.

## Install / upgrade

```sh
dsh plugin --profile <profile> add @fishdivinity/dsh-local-search
```

## Compatibility

- DSH `>=0.2.1-0 <0.3.0`; the page relies on the `plugins.row.config` slot that range declares.
- Windows only; engine prerequisites (Everything with `es.exe`, Anytxt GUI for content) are unchanged.
- A deployment that does not serve the settings namespace shows a hint instead of the form; the profile patch still configures everything.
