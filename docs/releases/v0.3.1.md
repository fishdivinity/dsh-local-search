## 这版做了什么

- 老宿主（0.2.x 早期）上「本地搜索」的配置卡片不会再整块消失：缺界面模块时它退成一行说明，工具与配置文件照旧能用。
- 启动时的配置写回如果没成功，页面上会直接告诉你原因，而不是只在日志里留一句。

## 怎么做到的

- `page`: 客户端半边缺 primitives 模块时降级而不是抛异常（console 里留一条原因）；`dsh.client.inject` 不再声明 primitives——宿主没有对应模块行就跳过，它本来只影响激活顺序。
- `page`: `/api/describe` 带上 `autoconfig.error`，页面在描述下方显示那一行。
- `page`: 两个后端选择器补上各自的 `id`（原来是 `undefined-everything` / `undefined-anytxt`，`label` 与 `aria-controls` 都指着它）。

## 升级

```sh
dsh plugin --profile <profile> add @fishdivinity/dsh-local-search
```

## 兼容

- DSH `>=0.2.1-0 <0.3.0`；仍然是 Windows + Everything（含 `es.exe`）/ Anytxt 的前提。
- 没有配置键变化，0.3.0 的 profile 直接升。

## What changed

- On older hosts (early 0.2.x) the Local Search configuration card no longer disappears whole: when the UI module is missing it falls back to one line, and the tools plus a hand-written config row keep working.
- When the startup config write fails, the page now says why instead of leaving it in a log.

## How

- `page`: the browser half degrades instead of throwing when the primitives module is missing (with the reason in the console); `dsh.client.inject` no longer declares primitives — a host without that graph row skips the name, which only ever ordered activation.
- `page`: `/api/describe` now carries `autoconfig.error`, and the page shows that line under the description.
- `page`: both backend selectors carry their own `id` (the DOM used to hold `undefined-everything` / `undefined-anytxt`, which the `label` and `aria-controls` pointed at).

## Upgrade

```sh
dsh plugin --profile <profile> add @fishdivinity/dsh-local-search
```

## Compatibility

- DSH `>=0.2.1-0 <0.3.0`; still Windows with Everything (`es.exe`) and/or Anytxt.
- No config-key change, so a 0.3.0 profile upgrades as-is.
