## 这版做了什么

- 整盘内容检索在「配置的检索根一个都不在」时不再整条失败：结果会说明它退回了工作区，而不是被输出校验拒收（0.4.3 在这个组合下会失败）。
- 这一版主要是地基：结果形状与「哪个引擎坏了」的修法不再各写各的，下一个后端进来时不会悄悄少字段。

## 怎么做到的

- 新增返回契约：两个后端只交原始行，`ref` / `engine` / `truncated` 与日期一处盖章；坏数据直接报错，不再静默变空结果。
- 探测收成一张注册表：状态工具、配置页、可复制诊断与首用写回遍历同一个结果；页面的状态行与修法也按键名派生。
- 开发期加了一层类型检查与几条机械闸（错误码对照、schema 默认值、工具输出 schema、装配接线）；发布物不变，仍是单文件、无构建。


## 兼容

- DSH `>=0.2.1-0 <0.3.0-0`；Node `>=24.9.0`（与 DSH 0.2.2 一致，比 0.4.3 收紧）。

## What changed

- Whole-disk content search no longer fails when none of the configured search roots exist: the result says it fell back to the workspace instead of being rejected by the output schema (0.4.3 failed that call).
- Most of this release is groundwork: result shape and "which engine is down" fixes are no longer written per site, so the next backend cannot silently drop fields.

## How

- A result contract: both backends return raw rows, and `ref` / `engine` / `truncated` plus date validation are stamped in one place; bad data is an error instead of an empty result.
- Probing is registry-shaped: the status tool, the card, the copyable diagnostics and the first-run write-back all traverse one object, and the card derives its lines and fixes from ids.
- Development-time type checking and a few mechanical gates (error codes against the docs, schema defaults, tool output schemas, route wiring); the published artifact is unchanged — one file, no build.

- Tool names, arguments, error codes and config keys are unchanged; a 0.4.x profile upgrades as-is.
