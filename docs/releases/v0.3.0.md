## 这版做了什么

- 配置换了形状，但你不用手改：旧的九个扁平键在启动时自动搬进新结构，搬不走时它们继续生效。
- 配置页按能力分节：先看到「文件名检索」「文件内容检索」，再在节内选 Everything 或 Anytxt，选中后只显示那个后端的字段。
- 第一次用的时候，插件会把探测到的 `es.exe` 路径和 Anytxt 地址写进还没设过的字段；引擎没开的话会提示一次。
- 保存会先校验：地址连不上、或 `es.exe` 路径上没有文件，就不写，弹窗问一次「仍然保存」；路径/目录/地址被拒这类硬错没有强行写入的出口。
- 描述下面一个**重置**，先摆出会清什么，确认后一次回到「刚装好」的样子：清掉引擎与上限、重新探一次、把能用的路径与地址填回去；检索范围不动。
- 路径字段保存时改成标准写法：`d:/alpha` 存成 `D:\alpha`；带空格的中文目录名照写。

## 怎么做到的

- `search` / `engines`：嵌套 schema 加启动迁移；新增 `/dsh-local-search/api/describe`，后端、字段与重置的范围都由 Host 描述，页面只负责渲染。
- `page`：`engine` 参数的 `auto` 现在跟随配置里选的后端；首用自动配置只做一次决定，之后清空的字段保持空着。

## 升级

```sh
dsh plugin --profile <profile> add @fishdivinity/dsh-local-search
```

## What changed

- The configuration has a new shape, and you do not have to edit it: the nine old flat keys move into the nested schema at startup, and keep working where the move cannot be written.
- The configuration page is capability-first: **File names** and **File contents** come first, then you pick Everything or Anytxt inside that section, and only that backend's fields show.
- On first use the plugin fills the fields you never set with the `es.exe` path and the Anytxt address it found; if an engine is down, it says so once.
- A save checks first: an unreachable address, or a path with no file on it, holds the write and asks in a dialog whether to **Save anyway**; a hard rejection (path, directory, address) gets no such way out.
- One **Reset** under the description shows what it will clear, then goes back to "just installed" once you confirm: the engine and limit settings go, a probe runs again, and what answers is refilled while the search scopes stay.
- Path fields are stored in one standard spelling: `d:/alpha` becomes `D:\alpha`, and non-ASCII directory names with spaces stay as typed.

## How

- `search` / `engines`: a nested schema plus a startup migration; a new `/dsh-local-search/api/describe` has the Host describe its backends, fields, and what a reset touches, and the page only renders them.
- `page`: the `engine` argument's `auto` now follows the backend selected in the configuration, and the first-run pass decides once — a field you clear stays clear.
